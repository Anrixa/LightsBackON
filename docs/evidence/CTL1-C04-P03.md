## Reproduced source-level issues

1. Both tablet entry paths in the shared scene hard-coded `contract.c01`; the C04/C03 previews displayed a C01 breadcrumb despite independently selected host contract identities.
2. The common `latch` event always reported C01 basement drainage; C04's actual optional `LATCH_SIGN_SUPPLY` is a 100-tick GRID-origin sign bonus, not drainage. Its activity measurement also incorrectly recorded `drain_latched`.
3. The original sign display reported instantaneous `SIGN.supplied` without visibly distinguishing the optional continuity latch. An illuminated sign does **not** prove 100 uninterrupted qualifying host ticks.
4. The C04 preview checked authorized switch IDs but did not enforce each switch's original target/field binding. A tampered mapping could put a misleading switch label on a physical station.
5. Malformed partial host snapshots could raise type errors instead of displaying UNKNOWN.

## Source changes

- Route tablet breadcrumbs through selected C01, C03, C04 contract identity, retaining the C01 production path and preserving unsaved preview behavior.
- Present C04-specific localized optional sign and required-supply events. Only C01's `LATCH_PUMP_DRAIN` records the C01 drainage activity marker. No change to host event generation.
- Distinguish `SIGN.supplied` from durable `mission.latched.LATCH_SIGN_SUPPLY` in a separate sign-side textual badge. Neither cable meshes nor instantaneous supply can grant the bonus.
- Require the exact five C04 switch-to-node/edge/field bindings and refuse incompatible definitions before creating scene markers.
- Unknown/malformed grid or mission payloads show UNKNOWN rather than invented boolean power, continuity or certification.
- No edits to electrical topology, mission timing, repairs, networking, save formats, shared Alder geometry, or campaign checkpoint files.
