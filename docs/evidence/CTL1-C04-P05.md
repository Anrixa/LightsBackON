# CT-L1/C04 P05 — Preview-only worksite approaches and neutral wayfinding

## Source authority and separation

- Baseline: merged-main `2ca4cc94e5d818f7c8e243c311834418d29b2a19` (CT-L1/C04 P04, independent Linux/Windows CI success #44342287137).
- Branch: `task/CTL1-C04-P05-preview-wayfinding`.
- Scope: **C04-only, unsaved, source-bound visual staging cues** at known street-level approaches to two mandatory repairs, three optional sign controls/worksites and the crew-van extraction area.
- The guide file lives at `scenes/mission/c04_preview_approaches.json`, outside the hashed `content/` tree; no rules_revision change, no mission logic, grid topology, ratings, checkpoint protocol, player movement, collision or Steam/network changes.
- C04's original blueprint remains authoritative: 4 PU independent `GRID → SPUR → SIGN`, optional 100-tick sign continuity, independently required five-service restoration.

## Engineering changes

1. Six centimeter-anchored guide positions match previously staged P02/P04 worksite probes: JE, JW, SPUR, sign switch, east-sign isolator and return to van.
2. Each cue is a neutral, non-emissive ground disc and billboarded localized caption. Labels explicitly identify required versus optional work and warn that the east-sign isolator is an alternate-feed hazard; none represents actual power or a verified route.
3. Full guide preflight runs **before** adding any scene marker or visual node. Refuse unknown/duplicate IDs, wrong contract, invalid types/coordinates, forged localization keys, sunken or displaced guide coordinates, or approaches too far/near from their corresponding scene marker.
4. The cue group is never added to the host target registry, does not modify the interaction callback, and cannot affect the van-zone admission check. It provides no navigation or movement authority and creates no collision shape.
5. C01/C03 remain byte-identical. Existing P01-P04 C04 station controls and host projection are preserved.
