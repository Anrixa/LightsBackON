## Implemented diagnostic
`scripts/diagnostics/c04_scene_accessibility.gd` exposes `Audit.inspect(scene)` and a structured readback with explicit per-site failures, capsule contacts, ray/selector state, markers and interaction distances. Only C04 scenes may be inspected.

1. **Eight worksite targets**: JW/JE/Spur panels, all five C04 switches. Standing locations are the previously staged P04/P05 curb-side points, with three companion breaker positions taken from existing panel approaches.
2. **Scene-bounded alignment**: compare the actual scene marker's global position to the host's projected target position, within 2 cm. This detects host-vs-scene anchor drift.
3. **Virtual capsule clearance**: query the actual physics world at eight standing points using the existing 35 cm-radius / 1.80 m-height player dimensions. A 4 cm temporary virtual height clearance avoids ground-contact false positives. The real player is **never moved** by the audit. This is *instantaneous standing clearance*, not a swept route or step negotiation.
4. **Headless line-of-sight**: invoke the production `InteractionVisibility.can_reach` with the real 2.30 m interaction length, each host target's original aim radius and scene physics layer 1; separately check `TargetSelector` in the direction of the intended station.
5. **Real-world negative control**: probe the back face of the west electrical cabinet at x=29.6, z=22.8. It is inside nominal target range, but the actual `CABINET_JW` collider must be the first physics hit and prevent an interaction ray from reaching `PANEL_JW`.
6. **Van worksite**: independently test virtual standing clearance and original host van-zone membership; never grant extraction or a checkpoint.
7. **Read-only invariants**: no movement, physics shape injection, host intent, grid/mission mutation, target registry edit, save write or fabricated navmesh/route graph.
