## Implemented

`scripts/diagnostics/c04_interaction_boundaries.gd` is a **read-only supplement** to P06's already verified scene audit. It refuses C01/C03 and fails closed if the P06 audit fails.

It scans each of the eight real C04 panel and switch markers using two virtual eyes separated across the real `content/interaction.json` effective sight-radius boundary: one **2.5 cm inside**, one **2.5 cm outside**. It uses the production `InteractionVisibility.can_reach` against actual scene collision and the production `TargetSelector` for direct aim, over-limit aim and facing away. Discrete probe origins are **not** a player walking route.

P07 retains exact C04 host target IDs and positions, and does not authorize or create new target registry entries. The audit records one pass/fail result per target, including the boundary in meters and required negative controls, with deterministic sorted IDs and a terminal `SOURCE_HEADLESS_ONLY` certification ceiling.

`tests/integration/test_CTL1_C04_P07_interaction_boundaries.gd` adds nine tests:

1. All eight boundary-matrix cases pass and remain explicit about non-route qualification.
2. For all eight targets, the **existing real SessionHost range callback** accepts nearby front-standing player positions and refuses out-of-range and forged-player calls. The test player is repositioned between separate samples only.
3. The actual reticle selector accepts a direct target, rejects looking away and rejects crossing the range boundary for all eight.
4. Both inherited JW and JE cabinet colliders block their rear sightlines within nominal interaction range (P06 previously established JW).
5. Each of three repairs shares the same physical marker and radius as its corresponding work panel; there is no separate remote repair range.
6. Unauthorized C03/foreign switches, arbitrary panel IDs and the C04 visual cue group cannot become host or UI targets.
7. Repeated scans produce the same output without player motion, camera change, host mutation, marker insertion or saved checkpoint.
8. C01 and C03 refuse C04-only audits; their separate save boundaries remain.
9. The P01–P07 ledger exists, references each phase and preserves preview/content revision isolation.
