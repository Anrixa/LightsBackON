# EXP014 A02 — Host-authoritative site contingencies and structural puzzle diversity

**Source base:** EXP014 A01 candidate PR #204, exact commit `3b2d9f71b45b3b6d5d248aef1b4ff1f8770c9b5b`. Stacked behind #199 → #200 → #201 → #202 → #203 → #204.
**Qualification:** `SOURCE_HEADLESS_ONLY_HUMAN_CONTROLLER_RELEASE_HELD`; no live-play, hardware, release or merged-main certification.

## Scope delivered

- Adds `site_contingencies_exp014_a02.json`: 200 opt-in source-bound post-intervention profiles across all 25 atlas regions. Each profile pins the **unchanged** location, mission's five task IDs, existing puzzle identity, worksite encounter key, original station target IDs, local risk/climate, intervention title/stakes and four original priority/resilience actions. No replacements or edits to the existing EXP012 A02 or four EXP013 books.
- Each existing site now has **two additional 3-stage contingency programs**, for 400 host-replayable new routes / 1,200 source-defined stages. Each new stage requires multiple independent station actions and host tick gates. The new programs reuse the three pre-existing SC station targets, preserving original target placement, source revision and geometry.
- Three **new** (not renamed old) host-side sequences are `quorum` (read a support station, wait for independent time-separated witness then seal), `reserve_lease` (arm a reserve stage, witness/transfer it, then release only after host settling), and `isolation_mesh` (isolate, independently verify, and close after timed interlocks).
- Their risk-specific guard requirements are sourced from climate/risk semantics: load balancing, logistics readiness, consequence stability and fault/hazard clearance. Missed windows, premature closure and upstream power loss create explicit host faults. Step retry, backtrack or restart are source-bound; owner-controlled recovery operates through the existing third station, not through client verdicts or a reset shortcut.
- Existing `operate_worksite` SessionHost command retains its authenticated peer, sequence-dedupe, rate/shape, proximity and optional visibility checks. Post-intervention contingency operation begins **only when the older site machine is solved**. Extraction remains locked until the opt-in contingency also passes.
- A new optional final `enable_site_contingency` argument defaults to `false`. Old sessions keep their original source content revision, hash, commands and behavior. The first-person experimental expedition stage explicitly enables the added post-intervention layer; the original twelve-contract campaign is unmodified.
- Both Windows export manifests include the new source book. `expedition_mission_stage.gd` presents actual host-controlled state/route, additional target actions, time-window/guard feedback and fault recovery. The noncolliding EXP014 A01 route renderer now switches to display the added source-driven three-phase contingency after the original four procedures finish.

## Independent diversity evidence

`tools/validate_exp014_contingencies.py` does **not** count action names, titles, cosmetic names or timer changes as distinct. It incorporates the old four-stage operation topology **plus the new** mechanical modes, station roles, guard dependencies and failure consequences.

**Initial A02 source result:** 155 distinct structural priority/resilience route pairs of 200, maximum structural reuse 6. Previous EXP014 A01 baseline: 112 distinct structural pairs and max reuse 16. This is an improvement in source and host-executable *procedural structure*, **not 155 new basic engine primitives or human-qualified individually sculpted 3D levels**.
