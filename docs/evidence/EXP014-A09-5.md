# EXP014 A09.5 — Integration Safety Review and Fail-Closed Corrections

**Parent:** A09.4 draft PR #217 at commit `a585e45302e87185da5c403ab46717693a62e765`. This follow-up is not a merge or a promotion.

## Source-audit defects corrected
1. **Break-before-make reset bypass.** A primary feeder could previously be reset while its destination still had an engaged standby arrival. Reset now refuses until the standby tie is explicitly released, regardless of whether the normal source is energized.
2. **Concurrent standby destination.** An alternative standby asset targeting the same node could previously be closed before that node was restored, because normal live-node connectivity did not include an unrestored destination. The host now refuses a second standby tie to an already connected destination.
3. **Dark reserve recharge.** An EXP04 receipt for the reserve anchor previously allowed replenishment even if all live supply to the anchor was isolated. Recharge now requires a **restored and currently energized** anchor, no engaged tie and one-shot usage.
4. **Restoration receipt/extraction bypass.** A09.3 only guarded a worksite decision, allowing the standalone EXP03 mission result to mark the five-task restoration complete. Opt-in regional sessions now also block the authenticated `request_extract` intent until host-owned regional preparation, suppress the EXP04 restoration receipt in `_update_progress` until that preparation, and reconcile `completed()`, `task_board().mission_completed` and the tick reply to the same host verdict.
