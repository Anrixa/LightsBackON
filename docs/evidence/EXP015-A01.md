## Actual new gameplay logic

**25 new authored regional emergency incidents**, one at the original first EXP05 OR-join dispatch (LV_004, LV_012, …, LV_196), with unique real A09 source topology and source-pinned feeder/tie connections. Each case also binds one of five existing regional hazard risk families to a **different containment protocol** and bounded managed-outage pressure. All 200 original LV IDs, 1,000 original JOB IDs, original finds, credits, and 12 legacy contracts remain unchanged.

When the new `enable_incident_response` opt-in parameter is on and the dispatch is an authored incident site, the host attaches a new `Response` state machine. The existing SessionHost `operate_worksite` action on the **original worksite board** is the sole client entry point; no new untrusted RPC, client-supplied feeder ID, position, success flag, clock or receipt.

The new chain is **survey → isolate → (standby transfer OR managed outage) → prepare → recover → certify**:

- `incident_survey`: checks an actual selected A09 regional strategy, which independently requires the appropriate original EXP04 restoration proof.
- `incident_isolate`: isolates the originally authored normal feeder via A09's host transition; this is mandatory before standby can close.
- `incident_transfer`: attempts the real A09 normally-open standby tie through the existing finite-reserve, live-source, break-before-make interlocks. Failed attempts do not advance the incident or consume reserve.
- `incident_managed`: alternatively authorizes a bounded locally recorded unserved-service pressure without pretending that feeder power has been restored. It is not another way to engage a tie or mint reserve.
- `incident_prepare`: requires the selected response and a real host-side regional site preparation.
- `incident_recover`: checks fault recovery evidence; where applicable opens the standby before resetting the normal incoming feeder; rejects unrecovered fault or externally disturbed context.
- `incident_certify`: verifies incident stages, restored switching topology and host preparation. Certification is a local host gameplay fact, not an EXP04 receipt or standalone mission completion.

While opt-in is active, host extraction and final original restoration-task issuance are additionally gated on incident certification. An omitted opt-in has **no incident dependency**; the A09 protocol, original save/economy and legacy C01–C12 authority stay in place. Host canonical state includes incident decisions/history for correct revision and replay detection, with new `EXP015_A01_` content revision isolation.

The module does **not** attempt to persist incident memory across process restarts; that remains a separately held production-save feature.
