## Gameplay implementation — actual host behavior

Adds a **new** incident chain on each of the 25 *second* original EXP05 OR-joins: `LV_007, LV_015, …, LV_199`. These do not duplicate or replace A01's `LV_004, LV_012, …, LV_196` initial junctions. No additional JOB IDs are created: the original 200 levels, 1,000 tasks, 200 lore collectibles, 12-contract original blueprint and EXP04/EXP05 rewards/save protocol stay unchanged.

The A02 source `scenes/expeditions/region_cascades_exp015_a02.json` binds each second-junction incident to the **second** real normally-open A09 regional standby tie, its exact normal incoming feeder, the regional critical/shelter service sites, the original fault signature, the genuine recovery procedure and one of five risk-specific managed-outage severity protocols. The independent Python audit verifies true source-tree ancestry; it does not inflate distinctness with IDs/prose/timing.

The opt-in `enable_service_cascade` on `Runtime.start` enables the state machine:
1. **`cascade_assess`** — requires host-selected regional strategy backed by original EXP04 receipt proof; observes whether the critical service is presently supply-ready.
2. **`cascade_trip`** — executes an actual A09 authenticated-host `trip_feeder` with the **original regional fault signature**. This creates a real modeled fault + isolation at the specified feeder, rather than a merely decorative caption.
3. **`cascade_backfeed` or `cascade_managed`** — the former attempts source-live, break-before-make standby tie via real A09 transition (spends finite reserve only when accepted); the latter records bounded unavailable-service pressure, with an additional cost when critical service was dark at assessment, and grants no fictional electricity.
4. **`cascade_prepare`** — invokes/uses actual A09 regional host preparation.
5. **`cascade_clear`** — authenticates original A09 `clear_fault` procedure; no arbitrary client-supplied fault proof.
6. **`cascade_reconnect`** — opens the temporary backfeed before resetting normal feeder, preventing two supply arrivals. A failed preflight cannot advance incident.
7. **`cascade_attest`** — verifies fault cleared, normal feeder reset, standby open and site prepared. Only then may opt-in restoration/extraction proceed; attestation alone does not grant mission completion or EXP04 receipts.

All actions use the **existing** `SessionHost.receive` → validated `operate_worksite` original board: transport peer, sequence, dedupe, rate, range and existing optional source-owned line-of-sight checks remain authoritative. The incident module trusts no client-supplied target IDs, position, fault signature, credentials, clock, repair success or rewards. Authoritative host state/worksite snapshot and task board expose cascade state and differentiated service pressure/finite reserve costs. `EXP015_A02_` session content revision includes original A09 regional source plus the new A02 recipe.

### Compatibility

A01 and A02 opt-in flags can be simultaneously enabled at **either** authored junction: only A01 starts at the first OR-join, only A02 starts at the second. Enable neither to retain the existing A09 behavior. An A02-only invocation at its original second junction is independently valid, but cannot bypass the original EXP05 receipt/route prerequisites.
