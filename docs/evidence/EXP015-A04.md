# EXP015 A04 — Post-finale feeder stress, finite-reserve fallback and restoration stabilization

## Scope and dependency

This change extends the original 25 finale dispatches (LV_008 through LV_200,
every eighth source-authored level). It is **stacked on the EXP015 A03 exact
head**, remains a draft and is not a production promotion. Activate explicitly
with `enable_regional_aftercare=true` alongside EXP015 A03 and A09. A01/A02
junctions are unaffected when the shared opt-in flags are enabled; the new
runtime activates only at the actual final site.

The source book, `scenes/expeditions/region_aftercare_exp015_a04.json`,
binds each authored event to its original A09 shelter feeder, standby tie,
fault signature, protected critical service, source recovery procedure and
five risk-specific post-repair retest procedures. All 25 regional topologies
are inspected against A03 and A09. Nothing is inferred from a user-provided
asset, event, proof, authority bit or receipt.

## New playable *host* logic (physical/controller qualification still HOLD)

A04 is not a renamed checklist. `expedition_regional_aftercare.gd` executes
**real A09 network state mutations**, without a new RPC:

1. `aftercare_assess`: requires valid A03 live-state signoff, captures original
   shelter energization; otherwise blocks.
2. `aftercare_trip`: trips the original A09 shelter feeder with the pinned
   regional fault signature; A03's service seal is thereby genuinely revoked.
3. `aftercare_transfer` or `aftercare_managed`: transfers via the original
   standby tie only if its source is genuinely live, break-before-make
   interlocks permit it and real reserve ≥ 2 PU; an accepted transfer **spends
   exactly 2 PU** from A09. Managed explicitly records a modeled local
   pressure for dark shelter service. That pressure is not A09 service debt
   or EXP04/production economy. A standby tie does not magically energize a
   finale site that lacks an original restoration receipt.
4. `aftercare_clear`: invokes the original `clear_fault` with the original
   recovery procedure; a forged procedure never advances.
5. `aftercare_release` then `aftercare_reset`: opens standby **before**
   resetting the original primary feeder. The A09 safety interlock remains
   authoritative, and no reset bypass exists.
6. `aftercare_verify` then `aftercare_signoff`: checks restored original
   feeder health, open tie, unchanged real shelter energization and a
   freshly valid A03 signoff. Subsequent feeder fault invalidates the A04
   `closed()` condition without tampering with saved original receipts.

A04 is optional and disabled by default. Only the existing
`SessionHost.receive` → `operate_worksite` authenticated worksite board
ingress can submit actions. Peer/session identity, deduplication, sequence,
range, physics-visibility if configured, mission/task progress and reward
ownership are unchanged. While this opt-in branch is active, raw reserve
recharge at its board is blocked to prevent evading the aftercare decision.
The existing A03 shield protects the actual shelter feeder and standby tie
from direct client switching outside the specialized fault/recovery machine.

## Independent evidence and test design

- Python `tools/validate_exp015_aftercare.py` independently audits all 25
  original A09 networks and the A03 finale book, recomputes actual original
  EXP05 branch receipts and source-live standby feasibility, rejects ID
  renamings and topology drift, reports 50 scenario projections.
- Original source projections (not physical gameplay): **11/25** critical-first
  and **17/25** resilience-first finale cases can engage the available
  standby tie after the earlier A03 decisions; the remaining cases require
  managed recovery. Neither case pretends the un-restored finale site has
  power.
- `tests/python/test_exp015_aftercare.py` mutates source authority, feeder,
  tie, source fault/recovery proof, retest protocol and pressure, plus
  reserve/no-fictitious-restoration invariants.
- `tests/integration/test_EXP015_A04_regional_aftercare.gd` executes 25 × 2
  **real network transitions** and verifies finite-reserve changes, rejected
  premature actions, breach of A03 proof during the fault, transfer
  release-before-reset, final live proof and late proof revocation. Selected
  authenticated original host scenarios reject foreign peers and direct
  reserve changes and confirm zero newly issued rewards. Opt-out and source
  forgery are tested.
- `tools/run_tests.sh` includes the source oracle on both platforms; Linux CI
  uploads source evidence even if later jobs fail. Existing Windows QA57
  export and smoke coverage remains unchanged.
