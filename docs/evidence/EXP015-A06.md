## Real new source qualification and host replay

A06 does not inflate the original 200 levels/1,000 tasks or assert new
physical scenes. Instead it verifies the mechanics introduced by the five
EXP015 phases actually compose across the *original three dispatch junctions*:

- **First OR-join (each region's slot 4):** A09 select critical-first or
  resilience-first using original EXP04 receipt fixtures, then perform the
  A01 managed emergency isolator/response through authenticated
  `SessionHost.receive`, certificate and original A09 feeder reset.
- **Second OR-join (slot 7):** attach the *same host-owned regional A09
  object* from process-local state with a new independent
  authenticated session; preserve original strategy and reserve, but reject
  carrying site preparation to this dispatch. Execute real A02
  feeder trip, managed supply shedding, source-verified recovery, safe
  reconnect and incident attestation.
- **Original finale (slot 8):** attach the *same regional A09 object*
  through a third independent authenticated host session. Run A03 critical
  service accounting and source-valid shelter preparation, then A04
  actual shelter-feeder trip/managed recovery/standby release and A05
  actual critical-feeder trip, priority or managed decision, true
  original reserve recharge (only where eligible), verified fault
  clearance/reset and live-source signoff. Capture complete A09 event and
  reserve facts, authenticated state and zero fabricated rewards.

The source-derived original EXP05 route outcomes remain 25/25 critical-live
for critical-first and 0/25 for resilience-first; the original A09
reserve anchor is genuinely receipt/energization eligible in only
3/25 critical-first cases and 0/25 resilience-first cases before a
critical-feeder trip. Do not invent more eligibility or supply.
Every site's original worksite preparation must be independently earned.
Decisions carry across host instances **only inside the current process**;
A06 does not prove process termination recovery or modify production
saves.

## Automated regression gates

`tools/qualify_exp015_region_replay.py` independently calls source validators
for A01, A02, A03, A04 and A05, verifies 25 distinct original A09 feeder
topologies, their first/second/finale source binding to 75 distinct sites,
the original A09 critical/shelter feeders and two normally-open ties,
and 50 independently recomputed source receipt scenarios. It writes a
reviewable JSON artifact. `tests/python/test_exp015_region_replay.py`
mutates site, tie, feeder, risk source and release qualification to
ensure disallowed drift is actually rejected.

`tests/integration/test_EXP015_A06_region_replay.gd` sends actual original
`operate_worksite` envelopes for all 25 × 2 route scenarios and verifies
the three host sessions' process-local network identity, preserved reserve,
real A01/A02/A03/A04/A05 side effects, 0 new rewards, and no premature
mission completion. It also verifies foreign peers cannot operate the
worksite, sequence deduplication after final signoff, and separate accounts
do not share network state. The test harness writes only test-fixture
profile receipts to isolated `user://` test directories: **not
production player completion, credits or saves**.

The full Linux and Windows `tools/run_tests.sh` suite includes an
independent source oracle and direct GDScript test-parser gate; Windows CI
retains QA57 original export/manifest/headless smoke. Linux CI retains A06
source evidence even if later tests fail.
