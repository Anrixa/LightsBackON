## What A09 actually adds

25 ORIGINAL regional root entry sites, one per A09 source region, are now distinct cold-source commissioning incidents. The existing A09 book and EXP01 atlas pin the exact entry/root, region ID, original 5 task IDs, two original A09 protected outgoing feeders, their real capacity/protection, true critical service site, finite reserve, and one of five original risk classes.

The first-stage mission is a **cold start**. There is no EXP04 restoration receipt and no electrical energization at the root when it starts. A client cannot declare root power, future branch power, a restored site or successful mission.

The authenticated original worksite board permits these exact steps:

1. `entry_survey`: authentic root with no EXP04 restoration and no active feeder isolation/fault, no prior preparation. Record original regional reserve and service debt.
2. `entry_isolate`: physically isolate **both** original first-route feeder edges through A09 `host_transition`, with verified rollback if the second edge fails.
3. `entry_critical` **or** `entry_transport`: release precisely the chosen original feeder under the A09 reset interlock. The other remains isolated until further risk and reserve proof; this is a genuine protection decision, not a caption.
4. `entry_contain:<original-source-risk-protocol>`: require the exact region-specific flood/conductivity/mechanical/structure/weather proof, reject forged protocols.
5. `entry_buffer` **or** `entry_managed`: commit original source model resources. `commit_entry_buffer` is a narrowly scoped **host-only** A09 network transition which debits exactly **2 actual original reserve PU**. `commit_entry_debt` records **2 PU actual region service debt**, preserving reserve. Both are one-shot, root-only, refuse already restored roots, and cannot be exposed as new RPC. Subsequent legacy original `prepare_site` is still called and results are cross-checked. This extra commitment is necessary because existing A09 root `prepare_site` is intentionally zero-cost before the root has an EXP04 restoration receipt; accepting that zero cost as a consumed reserve would be fabricated.
6. `entry_unblock`: reset the held original second route feeder only after source risk protocol and real reserve/debt decision. This prevents deadlocking the existing optional first-route campaign.
7. `entry_verify` and `entry_signoff`: prove **both** exact A09 feeder states healthy, actual site prepared, original root still unrestored and dark, exact reserve balance **and** original service-debt balance. Re-isolating a feeder invalidates signoff; resetting it returns to qualified state.

These operations change the actual process-local A09 regional network reservoir/debt, which survives the host's existing `attach_site` dispatch into its following original first-route site. The source-only test uses EXP04 receipts as **ephemeral fixtures** to demonstrate this handoff; it never claims a player actually restored a site or received rewards. Cross-process migration/restart and durable campaign reserve persistence remain **HOLD**.

The new final `enable_regional_entries` host flag defaults to **false**. When enabled it requires original EXP014 A09 networking and only activates at 25 source-pinned original region root sites. If A01/A02/A03 global flags are enabled, their existing source eligibility gates now recognize these roots **only with the explicit A09 entry opt-in**, avoiding illegitimate unauthored-site rejection while preserving original default holds. The original SessionHost principal, membership, sequence dedupe, 20-command/10-tick rate limit, position, range, original worksite RPC, content revision and reward boundaries stay unchanged. Direct `regional_buffer`, `regional_managed`, `regional_recharge` and feeder isolate/reset commands for the two protected root first-route feeders are rejected while this authority is active.
