# EXP015 A12.11 — Obsolete Host Lifecycle and Earned-Receipt Continuity

**Source parent:** A12.10 draft PR #256 exact commit `9182d3ecd11ec1795af5dfa9d3eebd7fdc24aca1`. This is a stacked **DRAFT / HOLD**, not a merge or release.

## Concrete bypass after A12.10

A12.10 rejects obsolete authenticated peer intents, but the former, still-allocated host object could continue `tick_host()` or call its underlying `SessionHost.tick()`. Both can advance local grid trips, mission clock, lock deadlines, EXP08–EXP015 scenario progress and host checkpoint revisions without new peer messages. The former host's progress/reward callbacks were also not checked against the current regional dispatch epoch.

## Source-only fix

- An A09-enabled SessionHost receives a **host-only** tick authority callback bound to its captured regional epoch. An obsolete host's direct `SessionHost.tick()` advances only rate-window time; no game simulation, mission, regional controller, checkpoint or revision updates execute.
- The ExpeditionHost `tick_host()` wrapper rejects before incrementing the authoritative tick, zone presence or bespoke progress, with `EXP015_A12_11_STALE_HOST_LIFECYCLE`.
- Task progress, new task reward issuance and collectible issuance fail closed for a stale regional dispatch, including host-local callback paths.
- **Previously earned** EXP04 receipt queue entries remain readable and acknowledgeable, so preemption cannot silently discard genuine unpaid rewards. No new rewards may accrue after preemption.
- Legacy/non-A09 sessions have no tick authority callback and retain their existing clock and mission behavior. No new network RPC, client time, source data, save schema, economy rule or production credit grant.

## New source integration regressions

The headless Godot test reuses 25 original source regions, authenticated SessionHost inspection to produce a genuine valid task reward before preemption, two host dispatches sharing each original account's regional network, and original live reserve strategy. It asserts stale wrapper ticks and direct SessionHost ticks cannot advance hash, source ledger or local clock; stale internal reward/progress callbacks cannot issue new receipts; already-earned receipts survive and acknowledge; the current host can still tick and spend exactly 2 PU; non-A09 sessions remain unaffected.
