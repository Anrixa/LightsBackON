# EXP015 A12.12 — Transactional Original Regional Dispatch Startup

**Parent:** EXP015 A12.11 source-only draft PR #257 at `d494c37d165bb729c86fd11f75cbc0ce339774fb`. **DRAFT / HOLD; no merge or tag.**

## Root cause

`ExpeditionHostSession.start()` calls `RegionalNetworks.acquire()` and advances the account-owned regional dispatch epoch before loading the rest of the authored EXP015 controllers and local SessionHost. A late failure can orphan a fresh registered region or preempt an earlier working source owner despite no replacement session completing startup.

## Implementation

- Capture original **process-local** account/region object identity and complete pre-start state, including feeder/fault/tie states, source receipts, site/epoch, reserve/debt, decisions and append-only event ledger, before attempting session startup.
- Keep the existing `Network.acquire()` behavior unchanged for direct host calls and compatibility.
- Wrap the whole synchronous host initialization. On failure, restore the **same** shared regional object in place; on a failed first start, remove only the newly created registry entry.
- Reject unexpected identity or epoch changes rather than undo a different host's source mutation; report `EXP015_A12_12_ROLLBACK_HOLD` for an unresolved rollback.
- Scrub the failed session's regional object/controller references. Successful starts still advance epoch normally; A12.6/A12.9/A12.10/A12.11 authorization remains enabled.
- No client-side dispatch epoch, new RPC, save schema, fabricated power or reward.

## Regression evidence (headless, pending CI)

25 real original finale/account regions, actual host session, failed second dispatch **after successful regional acquire** but before completing A01 source initialization, including a legitimate extra EXP04 restoration receipt applied during the attempted refresh. Assert exact restoration of the original snapshot and epoch, original session still authoritative and able to spend the original finite 2-PU strategy. A separate failed-first-dispatch test asserts there is no orphan registry entry and a later source acquire starts at epoch one.
