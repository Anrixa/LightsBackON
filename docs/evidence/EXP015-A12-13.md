# EXP015 A12.13 — Stale Outbound Snapshot and Source-Replication Authority

**Stack:** A12.12 draft PR #258, exact parent `c987a3713656816054d7a7344dd8ec5a4e9156a0`. Source-only **DRAFT / HOLD**.

## Measured/inspected authority gap

A12.10 prevents stale authenticated peer intents; A12.11 prevents obsolete host simulation ticks. An old, still-allocated SessionHost could nevertheless expose the shared original regional network's **new dispatch** through its old `snapshot()`, `publish()`, canonical `authoritative_state()`, and the ExpeditionHost task-board/authoritative read APIs. That risks disclosing successor feeder and reserve decisions or publishing a state under the wrong session revision.

## Implementation

- Reuse A12.11's strictly host-owned original-region dispatch epoch callback, already bound for all A09 sessions.
- Old `SessionHost.snapshot()` fails closed with `EXP015_A12_13_STALE_HOST_SNAPSHOT`; `publish()` emits no obsolete delta; `authoritative_state()` returns only a static, non-sensitive stale marker. Its state hash is independent of the successor's later regional decisions.
- `ExpeditionHostSession.authoritative_state()`, `task_board()` and the internal worksite snapshot refuse old dispatch reads before including the shared A09 state.
- The current legitimately authorized host still publishes its authoritative state, and the existing legacy non-A09 sessions retain normal snapshot, delta and task interfaces.
- No new wire messages, credentials, client epochs, persistence, power, monetary rewards, or human/controller release gates.

## New tests

A dedicated Godot integration test covers all 25 original region accounts with two sequential authenticated host startups on the same regional source, old legitimate snapshots before replacement, rejection afterward, no stale source hash drift as the current host legitimately spends 2 PU, and continued current-host snapshot availability. A second test checks a non-A09 legacy session's original snapshot and task interfaces.

## Protected baseline

The EXP014 A10.4 original SessionHost object remains pinned as a historical baseline. The protected-source gate also admits only the **exact** A12.11 and A12.13 source revisions by their independently fetched Git blob SHA-1; any other source drift fails closed. This is compatibility qualification, **not** independent external approval of a host-code change.
