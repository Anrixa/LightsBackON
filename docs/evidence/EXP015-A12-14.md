# EXP015 A12.14 — Obsolete Transport Lifecycle Fence

**Parent:** EXP015 A12.13 draft PR #259 at exact head `035529ce060202e924e8d49971bd4028b3be0583` (corrected CI #816 running when source work started). Source-only, stacked **DRAFT / HOLD**.

## Inspected gap
A12.10 denies old authenticated intents, A12.11 denies old ticks, and A12.13 denies old outbound snapshots. However, the original SessionHost also exposes five host-side lifecycle transitions: `admit`, `confirm_synced`, `remove`, `begin_after_briefing`, and `set_in_zone`. Their old implementations could continue mutating an obsolete host's crew, mission or equipment state after the next regional dispatch.

## Source correction
Reuse the already-existing **host-only** original regional dispatch epoch callback, without accepting client epoch input. Refuse obsolete `admit`, `confirm_synced` and `begin_after_briefing` with `EXP015_A12_14_STALE_HOST_LIFECYCLE`. Make obsolete `remove` and `set_in_zone` no-ops. Current regional dispatches and original non-A09 legacy hosts retain their lifecycle behavior. The already-earned EXP04 receipt delivery/ack path remains intact and separately guarded from new issuance.

## Original-source tests
The existing original A12.13 integration fixture runs an additional 25-region replay: authenticate old owner, replace it with a new owner, then attempt all five old lifecycle transitions, verify the old peer/revision/hash are unchanged, and independently confirm a current owner can admit/sync/remove a peer. A non-A09 original LV_001 session is tested for unchanged lifecycle behavior. No invented feeder, reserve, region, receipt or replay approval.
