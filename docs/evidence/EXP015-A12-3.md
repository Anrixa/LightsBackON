## Security and actual mechanical problem resolved

A12.2 allowed `anchor_defer` whenever the original reserve anchor was dark
and *some* blocker existed. An original tripped/isolated feeder could therefore
be mislabeled as a managed missing-source handoff even with all authentic EXP04
restoration receipts already present. A12.3 closes that bypass.

- **Managed dark** is valid only when the host's source path identifies a
  genuinely missing original EXP04 receipt and the anchor is actually dark.
  A pure isolated/faulted feeder is never an acceptable managed substitute.
- **`anchor_repair`** authenticates the *first actually blocked original
  feeder* on the unique root-to-anchor tree. The original source risk
  procedure must be supplied through the existing worksite host envelope.
  Actual A09 `clear_fault` (where faulted) and safe `reset_feeder` execute
  on that exact feeder; for a safe isolated edge, original source proof
  precedes reset. No client-selected feeder ID, new RPC or new synthetic source.
- Multiple genuinely blocked feeder edges are handled one at a time. If
  another source feeder is still blocked after reset, the encounter stays
  unresolved, rather than falsely reporting energized power.
- Source signoff is dynamically invalidated by subsequent feeder faults,
  isolations, standby conflicts or missing receipts.
- Generic original anchor-path `regional_isolate/reset` and direct
  anchor standby-tie manipulations are denied while this optional incident
  is active; existing internal host-owned A05/A09 operations remain subject
  to their original safety interlocks.
- Host content revision explicitly changes to `EXP015_A12_3_` for the new
  opt-in behavior. Default opt-out preserves previous campaign behavior.
