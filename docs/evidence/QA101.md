# QA101 — Reject missing tablet localization keys before applying snapshots

- Baseline: `e8aadffb36a84f84e5af3cbfdd1c4a58e44bde50` (QA100 merged).
- Scope: read-only Network tablet (S07), localized node labels, optional access hints and Objective descriptions.
- Defect: the tablet's snapshot gate checked that localization fields were strings but did not verify the keys exist. `UiText.t()` falls back to the raw key, so a stale or malformed snapshot could place internal `node.*`, `access.*` or `objective.*` identifiers in the player's UI.
- Fix: use `UiText.has()` during pre-swap validation of each node `name_key`, optional `access_key`, and Objective `text_key`. Reject an incomplete localization reference **before** updating `_view`, `_objectives`, focus or pending network request tracking.
- Regression: `test_QA101_unknown_tablet_localization_does_not_break_visit` at 1280x720 / 150% UI scale covers unknown/empty node keys, unknown/ill-typed optional access keys, an unknown Objective key, preserved focus/selection/in-flight Ping, actual Ping acknowledgment, and acceptance of a registered access hint.
- Validation command: `bash tools/run_tests.sh` on exact PR head, then Windows release export/smoke and QA51 isolated resource checks, followed by exact merged-main CI.
- No changes to authoritative simulation, save, mission, network transport, contract assets or original milestone status.
- No physical GPU or controller acceptance, human UX sessions, two-PC Steam F02/F06 qualification or publishing are claimed.
