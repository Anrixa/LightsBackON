# QA105 — Bound sparse tablet grid coordinates

- Baseline: `4bb823ea618b562105965e1a95e29f90449369fd` (QA104 merged).
- Defect: read-only tablet validation accepted any nonnegative integer column/row. TabletMap enumerates row indices up to their maximum, so a corrupt refresh with a huge coordinate can trigger pathological layout work and hang the interface.
- Fix: introduce an explicit 64×64 presentation-coordinate ceiling and refuse out-of-bounds rows/columns before any live snapshot state is modified. Authored C01 coordinates remain unchanged.
- Regression: `test_QA105_sparse_coordinate_overflow_is_rejected_before_layout` at 720p/150% rejects col/row=64 and col/row=1,000,000,000, preserves focus/selection/pending Ping, accepts valid coordinates.
- Gates: exact-head Linux/Windows full tests, Windows export/smoke, QA51 isolates and postmerge exact-main CI. This is a presentation safety limit, not a change to simulation or content.
- Physical/GPU/controller, Steam/F02, human UX and publishing not verified.
