## Reproduced defect

Godot 4.7.2's `NetworkTablet._rebuild()` always allocated and configured a `TabletMap` tree, but parented it under `_body_left` **only when the Network tab was selected**. On Objectives, each map was an unparented Node with many controls. Subsequent scale/device/tab rebuilds overwrote the `map` reference and lost ownership of the detached tree. Production reflow could therefore leak controls and resource handles.

The independent `tools/qa_resource_probe.py` starts separate **verbose headless Godot processes** for empty baseline, SIM08 logic, DS04 presentation and DS05 isolated UI cases. It records RID/ObjectDB warnings to per-OS JSON and logs without hiding engine errors. `.github/workflows/qa-resource-probe.yml` runs the probe only for relevant changes or explicitly dispatched QA, so every unrelated PR need not incur the extra load.

## Corrective code and regression guards

- Allocate `TabletMap` **only** for the Network tab; Objectives uses only its owned `ObjectivesScroll` tree. The `map` reference is null on Objectives.
- Controller zoom triggers do not dereference a nonexistent map; the hidden Center action also checks it.
- The existing live DS05 integration verifies Objectives has **no** unparented map and changing back to Network creates a parented, usable graph.
- QA probe now fails its relevant cases if CanvasItem or DummyTexture regress above the observed **zero** ceilings. Residual ObjectDB/font warnings remain visible and are not silently tolerated as resolved.
