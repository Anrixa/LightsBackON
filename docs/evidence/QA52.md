**Status:** Production RefCounted ownership defect **FIXED in code**, cross-OS probes and full source CI PASS at `fef76f70ce58fd0f17be97f458b2dca958d2d1e2`. Final evidence/guard commit CI and physical GPU acceptance remain pending. QA issue #51 stays **OPEN**.

**Base:** `main` `9b83bce09cd6a58181daf9b37491f03397f68b20` (QA51 merged). **PR:** #56; branch `task/QA52-residual-resource-diagnostics`.

## Exact defect and independent reproduction

`OfflineSession` is a `RefCounted` owner of the C01 host services and an `IntentOutbox`. Its outbox's locally bound `func(...): return host.receive(...)` and direct `replied.connect(_on_reply)` retained a path to the owning session, forming a reference cycle after the game scene was destroyed. Headless Godot shutdown reported RefCounted object graphs from former sessions, although the mission and UI nodes were explicitly freed.

Introduced `tests/integration/test_QA52_session_lifetime.gd`, which initializes the **actual C01 offline session**, captures only `WeakRef` handles to session, authoritative host and outbox, drops the last strong session reference, and asserts that all three are immediately released.

**Red proof:** [CI #41952770993](https://github.com/Anrixa/LightsBackON/actions/runs/41952770993) at `a06c90cc4604531fd90f6d68aa54e67a87cc0d63` failed this new test on Linux and Windows: **all three** weak handles remained alive. Its isolated [QA run #41952771059](https://github.com/Anrixa/LightsBackON/actions/runs/41952771059) showed one host fixture with 21 leaked ObjectDB instances.

## Correction

Added `scripts/gameplay/offline_outbox_bridge.gd`, an intentionally non-owning transport adapter. It stores **weak references** to the host and owner, forwards unchanged command bytes to `SessionHost.receive(PEER_ID, bytes)`, and relays unchanged responses to the session. The `OfflineSession` retains the bridge **strongly** in `_outbox_bridge` for exactly its own lifetime, because Godot's `Callable` does not keep a temporary `RefCounted` target alive by itself. This prevents both a dangling callback and the original owner/outbox/host cycle.

An intermediate version held the bridge in a setup-local variable. Its [CI #41953238276](https://github.com/Anrixa/LightsBackON/actions/runs/41953238276) correctly exposed null-target send failures, **not** a legitimate passing result. The bridge is now a session field; full mission tests and C01 reference checks were rerun and passed.

The command, sender peer ID, host validation, rate limits, grid simulation, mission objectives, save format and input bindings did not change. If a stale outbox is used after its host has been released, the bridge returns a diagnostic `SESSION_GONE` refusal instead of executing an invalid host pointer.
