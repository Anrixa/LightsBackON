- **Date:** 2026-11-05 UTC.
- **Status:** **DIAGNOSTIC VERIFIED**, not an assertion that the outstanding warnings are fixed or that physical Windows memory is acceptable.
- **Canonical base:** `main` `c7a7be168f00eec3cd23c24584a530f1c6e20815` (QA52 merged and post-merge CI green).
- **Branch:** `task/QA53-font-renderer-lifetime`; [PR #57](https://github.com/Anrixa/LightsBackON/pull/57).
- **Issue:** [#51](https://github.com/Anrixa/LightsBackON/issues/51) **remains open**.
- **Scope:** diagnostic integration tests, independent Linux/Windows pinned-engine probe, bounded regression limits and test-runner settling option only. Original 66-task backlog, C01 simulation, host identity, save schema, Steam, 3D assets and user-facing UI logic unchanged.

## Baseline

QA52's verified fix broke a real `OfflineSession → IntentOutbox → session` RefCounted cycle. The full hosted Linux Godot 4.7.2 suite still reported at shutdown **4 CanvasItem, 21 ObjectDB, 8 ShapedText and 1 FontRID** warnings. This is exit-time headless output, **not** a measured exported-game memory leak.

## Isolation design

`tests/integration/test_QA53_font_lifetime.gd` verifies weak-reference lifetime for:

1. Dynamically created `Theme` and the `StyleBox` it owns.
2. One and three independently constructed `MainMenu` scenes, including their themed resources.
3. Stock and project-font `Label` controls instantiated, shaped and freed.
4. Three standalone, unused native `ConfirmationDialog` windows.

The independent `tools/qa_resource_probe.py` runs each family in a separate pinned Godot process on Linux and Windows, preserves the engine's verbose logs, and compares 2 versus **30** idle frames between final test and engine shutdown. `tests/run_tests.gd` adds **opt-in** `--settle-frames=30`; default remains exactly two frames. No logger or warning is suppressed.

## Evidence from independent 4.7.2 Linux and Windows runs

| Isolated case | CanvasItem | ObjectDB | ShapedText | FontRID |
| --- | ---: | ---: | ---: | ---: |
| Empty no-script baseline | 0 | 0 | 0 | 0 |
| Theme and owned style WeakRef checks | 0 | 0 | 0 | 0 |
| Three stock Labels, with and without forced shaping | 0 | 0 | 0 | 0 |
| Three project-themed Labels, with and without forced shaping | 0 | 0 | 0 | 0 |
| Three unused native ConfirmationDialogs | 0 | 0 | 0 | 0 |
| One fully constructed and freed main menu | 0 | 12 | 2 | 1 |
| Two DS01 menu integration cases in one process | **2** | **15** | **4** | **1** |
| Three fully constructed and freed main menus | **3** | **18** | **6** | **1** |
| Same two DS01 cases with 30-frame settling | **2** | **15** | **4** | **1** |
| Same three menus with 30-frame settling | **3** | **18** | **6** | **1** |

- Both hosted OSes produced the same counts on [QA probe #41956737665](https://github.com/Anrixa/LightsBackON/actions/runs/41956737665). The explicit font-shaping isolates additionally passed on [QA probe #41957124143](https://github.com/Anrixa/LightsBackON/actions/runs/41957124143).
- `MainMenu` nodes, themes and owned styleboxes all passed their `WeakRef` release assertions. The residual exit-time counts therefore **cannot be attributed to an obviously retained menu node or dynamically built Theme resource** by this evidence.
- Residual verbose owner classes in the menu probe are `FontFile`, `DPITexture`, `Image`, six `StyleBoxFlat`, and one `TextParagraph` per menu, plus corresponding TextServer RIDs. These are identified class names, not proven references or a diagnosis of whether an exported game grows memory across runs.
- A single test **without** the full menu tree reports zero residual warnings for stock Labels, project-themed Labels, and standalone dialogs, even when their text is shaped. The residue is reproducibly associated with constructing the **complete menu**, not mere use of Noto Sans or a Theme.
- Thirty extra frames did not change any counts. Increasing the arbitrary runner shutdown delay is therefore **not an evidence-based fix**.
- A controlled experiment removed the early `ThemeTokens.build` allocation at menu startup, leaving only the responsive-layout build. This **increased** menu ObjectDB warnings by **one** on each OS (15→16 for the two-test DS01 case, 18→19 for the three-menu case), without reducing CanvasItem or ShapedText. The unhelpful experiment was explicitly **reverted**; the shipping menu code is unchanged.

## Regression ceilings added

The existing QA51/QA52 zero-leak controls remain intact. QA53 now fails its dedicated Linux/Windows workflow if the plain/theme/font/dialog isolates gain **any** CanvasItem/ObjectDB/font/shaped text warning, or if the reproducible complete-menu teardown cases exceed their observed bounds. The remaining warnings are **not silently accepted as safe**; these are *non-regression ceilings* on already observed engine exit output, not release gates.

`tests/python/test_qa_resource_probe.py` exercises the new measured ceilings and the 30-frame comparison args. This keeps exact counts reproducible while issue #51 stays open.
