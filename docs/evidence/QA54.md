## Reproduction and hypotheses

QA53 verified a reproducible, cross-OS menu-specific shutdown signature: single complete menu **0 CanvasItem / 12 ObjectDB / 2 ShapedText / 1 FontRID**, triple menus **3 / 18 / 6 / 1**, whereas standalone owned Theme, themed shaped Labels, and native ConfirmationDialogs produce zero. Menu nodes, themes and owned styles pass WeakRef release; 30 additional idle frames have no effect.

QA54 introduces six individually isolated *synthetic* menu component configurations, adding one structural family at a time: (1) theme + background + Scroll/Center/Panel/Margin/VBox; (2) six wrapped, font-shaped Labels; (3) buttons; (4) ConfirmationDialog; (5) responsive theme replacement; (6) self-referencing signal callbacks and button focus.

In addition, three exact PackedScene variants distinguish never-entered scene resources, entered scene without a script, and real inherited `MainMenu._ready()` with only `_layout_for_size()` overridden to a no-op. Every synthetic stage constructs a tree, attaches it to the actual SceneTree for layout, validates owned control/Theme/Panel WeakRef release after teardown, and runs in an **independent** pinned Godot process with `--verbose` so per-stage ObjectDB/RID deltas and class histograms are preserved. QA53's complete menu and DS01 tests remain separate baseline controls; diagnostic fixtures stay excluded from production tests.

These staged configurations are *not exact equivalents* of the shipping menu. A zero-result stage can only narrow a hypothesis, not prove a corresponding production subsystem innocent. No speculative UI patch, renderer pin change or warning suppression is made.

These observations establish that generic themed scrollable controls, representative wrapped labels, buttons, dialogs, theme rebuilding and focus/signals alone do **not** reproduce the residue. Merely loading/instantiating the real PackedScene or entering its empty controls is also clean. **The full MainMenu initialization path reproduces the warnings even without _layout_for_size()**. The diagnostic has narrowed the remaining owner to the actual menu's startup behavior or its interaction with the engine; it has **not** proven an individual faulty statement, nor fixed the warnings. Unconditionally removing responsive layout would be an unsupported regression.

Eight individually clean fixtures are now gated at zero engine shutdown warnings. The true no-reflow menu fixture is bounded at its observed 0 CanvasItem / 12 ObjectDB / 2 ShapedText / 1 FontRID; this ceiling is an anti-regression threshold, **not** a declaration that the residual is safe. QA53's existing menu-specific limits remain unchanged. No gameplay or UI code was modified.

**Execution caveat:** both OSes are GitHub-hosted headless processes. These results are not target GPU memory measurements.
