## What QA58 adds

QA57 validates one source-pinned Windows export capture's engine boot line, hashes, CSV chronology and F9 scenarios. QA58 adds observed viewport width/height to the already opt-in local QA56 frame CSV and compares **four independent captures**: two with fixed 1280x720 viewport, two with fixed 1920x1080 viewport.

The comparer recomputes the QA56 and QA57 results from original files and rejects:
- Stored reports that differ from the recalculated raw data or modified CSV/log hashes.
- Missing/incomplete scenario evidence, GPU counters or source-pinned exported package.
- Duplicate random session IDs, different build hashes, GPU names/drivers or Windows versions.
- Unsupported or changing viewport dimensions and missing resolution repeats.

It outputs P95/P99/max Godot engine-loop frame time, process RAM/private memory and dedicated GPU memory peak/delta comparisons. Thresholds of 33.3 ms engine-loop P95, 64 MiB RAM/private peak difference and 128 MiB dedicated-GPU peak difference are **triage triggers only**, not release budgets or proof of leaks. The successful technical label is COMPLETE_FOR_MANUAL_REVIEW, **never** release PASS. The release gate always remains PENDING_PHYSICAL_AND_HUMAN_REVIEW.

Godot viewport dimensions are not verified monitor output or GPU present timestamps. Existing QA56/QA57 CSV readers remain backward compatible, but QA58 needs new six-column captures recorded after this commit.

## Physical Windows procedure (not performed in hosted CI)

1. Export one clean build whose EXE, same-name PCK, build_manifest.json and source checkout HEAD match, with Godot 4.7.2 Compatibility renderer. Record physical GPU and driver.
2. Set the Godot viewport to **1280x720** and do not resize during a capture. Run the capture below twice as two independent sessions. For each capture, follow F9 segments in order: initial menu (30s), first repair mission path (60s), >=20 tablet/scale operations (30s), >=20 accessibility/pause transitions (30s), return to menu (20s), then quit normally. These are minimum post-warmup F9 spans; use longer intervals where needed for real operations.
3. Repeat twice at **1920x1080** with the viewport fixed through each full session. Keep Windows power and driver conditions comparable. Preserve redacted screenshots/video separately.
4. From a clean Windows source checkout matching the export, execute once for each of four runs:

~~~powershell
Set-Location C:\LightsBackOn
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\Start-QA56-WindowsCapture.ps1 -Executable .\build\windows\LightsBackOn.exe -OutputDirectory .\build\qa56 -MaxSeconds 900 -SampleSeconds 2
~~~

5. Supply the actual four random capture directory names printed by the launcher, replacing placeholders CAPTURE1 through CAPTURE4:

~~~powershell
py -3 -m tools.qa58_compare --capture .\build\qa56\CAPTURE1 --capture .\build\qa56\CAPTURE2 --capture .\build\qa56\CAPTURE3 --capture .\build\qa56\CAPTURE4 --output .\build\qa58-comparison.json
~~~

A coherent package returns QA58_COMPARISON=COMPLETE_FOR_MANUAL_REVIEW; invalid evidence exits with code 2 and INCOMPLETE. No tool uploads data or reads player profiles.
