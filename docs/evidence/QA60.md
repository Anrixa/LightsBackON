## Identified user-visible defect (source inspection)

MissionRoot's `_on_action_replied()` displayed a generic **Accepted: Interact** banner for *every* successful host response, including internal `heartbeat` liveness commands sent automatically while a repair lock is held. This overwrites genuine repair feedback repeatedly and can mask refusal/mission-event messages. Tool-switch acknowledgements likewise obscured more relevant text already represented in the HUD. Other status messages were written directly to a Label and never expired, allowing stale confirmations or refusals to remain over the game world. Its fixed 720px banner width was not fitted to compact viewports.

## Engineering changes

1. Ignore heartbeat acknowledgements and failures in the user-facing banner (host still processes each heartbeat normally). Ignore successful equip confirmations; the tool HUD already identifies the selected slot. Preserve rejection text for *real* player commands.
2. Route accepted actions, refused actions, trip/drain/verified events, recovery and save-error notices through one `_show_feedback()` presentation method with explicit timing.
3. Configure **4s** ordinary and **9s** important message retention under `content/offline_solo.json`, using integers to preserve content-validator constraints. Expire transient messages only during unpaused first-person play, never behind the paused UI or network tablet.
4. Treat a confirmed save-system failure as persistent and non-overridable by ordinary host replies. Do not imply saving succeeded when it did not; display stays until the scene exits.
5. Fit the banner width to the viewport safe area at compact and standard sizes; keep it above the central interaction area.
