## Reproducible user-facing defects

1. A resumed C01 session previously instantiated a fresh MOVE-stage tutorial even if its checkpoint already contained diagnosed/isolated/restored repairs. A completed first repair could never trigger the full tutorial again; the guide could become permanently stuck in an impossible earlier step.
2. CheckpointCodec intentionally excludes meter snapshots. Merely reading an isolated repair's durable state must *not* falsely show valid meter evidence on load; a new inspection is required before continuing.
3. A locked repair's actionable prompt contained generic "Continue repair" and a *current* state but not the next authorized repair stage. When the wrong tool was equipped the required tool appeared, but the operation was still not named.

## Changes

- Add monotonic, data-driven `OnboardingGuide.sync_from_world` reconciliation, using authored step-event IDs rather than independent or corrupted tutorial flags.
- In the live MissionRoot, rehydrate the guide only after a valid restored checkpoint; derive progress from the authoritative repair state and live meter snapshots. A partially restored repair with no meter snapshot starts at MEASURE and proceeds to REPAIR once fresh measurement confirms a previously isolated panel. A restored first repair shows COMPLETE.
- Reconcile after accepted inspect/repair replies. Unaccepted replies cannot advance the guide.
- Show the next legal repair stage beside the existing localized tool requirement; blocked actions remain blocked and never alter simulation. Reuse existing UI translations so `content/` bytes and the checkpoint content_revision are **unchanged**.
- Add QA61 regression cases for guide monotonicity, hint lifecycle, real offline host repair prompts and live MissionRoot rehydration.
