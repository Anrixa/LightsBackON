# QA64 — Keep repair lock heartbeats active in the network tablet

- **Date:** 2026-11-06 UTC.
- **Base:** `ece726409448f981a4c93f62993314e1745c6eff` (QA63 merged).
- **Branch:** `task/QA64-tablet-repair-heartbeat`.
- **Scope:** Offline C01 scene heartbeat scheduling; no host authority, timer constants, save schema, content revisions, Steam or third-party assets changed.

## Defect and correction

The `MissionRoot._physics_process` host tick continues while the tablet is open, but its early return bypassed the regular repair-lock heartbeat. Since the host releases locks after 20 ticks without a heartbeat, examining the tablet for two seconds could silently abandon an in-range repair lock.

Move the existing heartbeat cadence above the tablet-only world-input/targeting return. The same `_send_heartbeats()` retains the existing proximity predicate; out-of-range locks must still be released by the authoritative host. The tablet still suppresses player controls and world interaction.

## Automated acceptance

`test_QA64_tablet_keeps_repair_heartbeat_clock_advancing` instantiates the live mission scene, opens the tablet, advances six 250 ms production physics frames and asserts that the host continues to tick, the world controls remain blocked, and the heartbeat accumulator has rolled into the next period. Existing G04 lock-expiry tests retain the negative liveness gate.
