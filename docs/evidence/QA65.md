# QA65 — Fail-closed menu on unreadable or future-schema checkpoint

- **Date:** 2026-11-06 UTC.
- **Starting main:** `6103a2daa268224b4cd031a72f02c02a9b03bbb8` (QA64 merge).
- **Branch:** `task/QA65-fail-closed-new-shift`.
- **Scope:** Offline main-menu save-entry safety only. No save schema, checkpoint bytes, deletion/migration, Steam or content changes.

## Defect

MainMenu previously interpreted every checkpoint error as the absence of progress. It displayed New Shift as enabled and launched an unsaveable mission even after corrupt/newer-schema checkpoint detection. The persistence writer already refuses replacement, but the menu misled the player into spending time in a game that could not save.

## Correction

Treat `status.ok=false` as an explicit launch blocker, show the fault code, hide Continue and disable New Shift. A controller can still reach Quit. On every launch action, re-read the actual checkpoint state, so a save that appears or becomes unreadable while the menu is open is not silently ignored. When valid progress exists, retain the explicit replacement confirmation. No unreadable save is rewritten or moved by this UI change.

## Automated coverage

`tests/integration/test_DS01_menu_reflow.gd` seeds a malformed checkpoint and a separately valid **future-schema** checkpoint in isolated test-only profile roots. It asserts both block New Shift, do not set the launch flag, and preserve original checkpoint bytes. Both roots are removed by the test.
