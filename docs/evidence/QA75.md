# QA75 — Reset evidence scroll on network-node selection

- Date: 2026-11-06 UTC
- Starting main: `e437d9743276d219e06e508b5f44b35ce62cd162`
- Branch: `task/QA75-reset-evidence-scroll-on-selection`
- Scope: UI navigation/readability only; no simulation, save, content or protocol changes.

## Defect
`NetworkTablet.select()` replaces the detail-pane content in the same `ScrollContainer` without resetting its scroll offset. A user reading a long meter record and focusing a different node can land partway down the new record, without seeing its heading or current status.

## Correction
On a genuine node-selection change, rewind the evidence pane before filling the new node's details. Keep the existing scroll position for same-node live refreshes, and preserve the QA71 selected-node D-pad backlinks.

## Automated regression
`test_QA75_new_selected_node_resets_long_evidence_scroll` creates two genuinely scrollable node views in the real tablet UI, scrolls the first, selects the second and asserts its detail pane starts at the top after layout.
