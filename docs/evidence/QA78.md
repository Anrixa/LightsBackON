# QA78 — Correlate tablet replies with current visit and selection

- Date: 2026-11-06 UTC
- Starting main: `793d23bb7292245e2e951a223ab4915424fe1191`
- Branch: `task/QA78-tablet-reply-visit-correlation`
- Scope: read-only Network tablet UI; no transport protocol, host authority, save or content modification.

## Defect
QA67/70/74 filtered replies when the tablet was hidden, on another node or in Objectives, but a delayed reply for the same target could become relevant again after close/reopen, or after selecting away and back (the ABA case). A reply from a previous tab visit could similarly be presented as a new outcome.

## Fix
Listen to the existing local outbox `sent` signal to correlate each dispatched inspect/ping envelope with its sequence. Invalidate pending requests when closing/reopening, changing selected nodes, replacing a removed selection or leaving Network. Only present replies for outstanding, current requests. Existing in-process host replies still flow immediately through `replied`; no new commands or network fields.

## Regression
`test_QA78_delayed_same_target_reply_is_ignored_after_visit_selection_or_tab_change` covers close/reopen, node ABA, tab roundtrip, and newly issued same-target replies.
