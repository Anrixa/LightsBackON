# QA92 — Validate tablet tab transitions

- Baseline: `59f7eab96c598eb7e3f26e8a929a8ddb8d44aa93` (QA91).
- Branch: `task/QA92-validate-tablet-tab-transitions`.
- Defect: the tablet's public `_show_tab(t)` blindly accepted arbitrary tab identifiers and pre-snapshot requests. An unexpected/stale callback could change `tab` to an unsupported value, call `_rebuild`, and dereference a nonexistent tab button during focus restoration. A call before the first `show_data` also attempted to focus uncreated controls.
- Fix: accept only the two declared tab identifiers and only when a view has been initialized; invalid and premature callbacks are no-ops. Valid tab behavior, read-only access rules, pending reply invalidation on *real* tab changes, and focus graph remain unchanged.
- Regression: `test_QA92_tablet_ignores_invalid_and_preinit_tab_transitions` tests pre-snapshot navigation; unsupported and empty tab names during an active 720p/150% Network visit; focus and pending acknowledgment preservation; legitimate Objectives→Network navigation afterward.
- Required gates: exact-head Linux/Windows `bash tools/run_tests.sh`, Windows release export/headless smoke, QA51 resource-lifetime probes, post-merge main CI.
- CI cannot qualify physical Windows GPU/P95/memory, real controller UX01, V09 human sessions, F02/F06 two-PC Steam, or publishing. #51 remains open.
