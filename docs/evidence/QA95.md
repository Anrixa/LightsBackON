# QA95 — Block reentrant tablet-origin sends

- Baseline: `219302de2c3c4aa569c9b271a0eaa9d8fb624b85` (post-QA94).
- Branch: `task/QA95-prevent-reentrant-tablet-intents`.
- Defect: the outbox's synchronous `sent` callbacks could reenter `ping_selected`/`inspect_selected` while a tablet intent was being dispatched, resetting the expected sequence and losing or misattributing the original response.
- Fix: the tablet refuses a nested send while its synchronous dispatch scope is active. External outbox-originated sends remain separately protected by QA90–QA91.
- Regression: `test_QA95_reentrant_tablet_action_cannot_corrupt_original_dispatch`. A deliberately reentrant callback attempts a second Ping while the original is sending; the test verifies only one command, retained correlation and successful genuine feedback at 720p/150%.
- Required: exact-head Linux/Windows full tests, Windows release export/headless smoke, QA51 resource checks and postmerge main CI. No physical GPU, controller, user study, Steam transport or publishing verified.
- Scope: read-only tablet UI; no mission, networking, save, reward or content changes.
