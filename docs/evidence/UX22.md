# UX22 — controller focus recovery when checkpoint state changes

## Root cause
The main menu can show a valid checkpoint at first and later discover an unreadable/newer one during an action. Disabling New Shift or hiding Continue can leave focus on an invalid control. On Godot, focus may be lost immediately when the button becomes disabled, so inspecting focus *after* changing UI state is too late.

## Code
- Keep a reference to the existing Quit action.
- Capture the previously focused control before applying the latest save status.
- When focused New Shift is disabled, focus an available Continue action or Quit; when focused Continue is hidden, choose enabled New Shift or Quit.
- Leave unrelated focus unchanged and preserve all checkpoint safety decisions and non-destructive confirmation behavior.

## Regression
`tests/integration/test_DS01_menu_reflow.gd` checks disabled New Shift, disappearing Continue, and newer-schema recovery on the actual menu scene.
